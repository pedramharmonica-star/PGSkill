# پیش‌نیازهای نصب (سند رسمی، ویرایش ۱۴۰۴۰۳۱۵)

منبع: PayamGostar-Installation-Requirements-V2-final (۱۳ صفحه). **این سند جدیدترین و معتبرترین مرجع سخت‌افزار و نرم‌افزار پایه است** و بر اعداد RFI، دک‌ها و FAQ مقدم است. مواردی که در سند با رنگ آبی مشخص شده‌اند «پیشنهادی» برای بهبود سرعت‌اند؛ بقیه **الزامی**‌اند.

### محاسبه هسته CPU برای سرور مجازی (مثال سند)
Core لازم = (Benchmark لازم جدول) ÷ (Benchmark چندنخی CPU ÷ تعداد Thread).
مثال: ۲۵ کاربر روی Xeon E5-2690 v4 (Benchmark ۱۹۳۷۰، ۲۸ Thread): ۱۹۳۷۰÷۲۸≈۶۹۱؛ ۱۲۵۰۰÷۶۹۱≈**۱۸ Core**. پیشنهاد: کل سوکت (اینجا ۲۸ Core) اختصاص داده شود، چون تخصیص بخشی از سوکت باعث Align نبودن و کندی می‌شود.

## ۲. نکات مجازی‌سازی
- CPU، RAM، Disk و Network حتماً **Dedicated** باشد.
- مجازی‌سازی روی **Hyper-V client** پشتیبانی نمی‌شود (Hyper-V Server/ESXi مشکلی ندارد؛ RFI: VMware ESXi و Microsoft Hyper-V).

## ۳. نکات الزامی
1. دیتابیس و بکاپ روی دو درایو جدا (در صورت امکان دو هارد جدا).
2. بیش از ۱۵۰ کاربر: هماهنگی قبلی با موفقیت مشتری.
3. بهتر است هر نرم‌افزار روی سرور اختصاصی باشد. سرور پیام‌گستر نباید خاموش شود (فعالیت‌های سیستمی و بکاپ) و نباید به‌عنوان کلاینت روزمره استفاده شود.
4. اگر CPU اختصاصی کمتر از مقدار اعلام‌شده باشد، **حداقل ۸۰٪** منابع لازم است و با تعهدنامه، مسئولیت کندی بر عهده مشتری است.
5. (پیشنهادی) بیش از ۵۰ کاربر: دیتابیس و وب روی دو سرور جدا.
6. (پیشنهادی) SSD، NVMe یا M.2 برای ویندوز و نرم‌افزار. SSD برای دیتابیس اگر سرور HP، MikroTik یا SuperMicro با RAID Support است؛ وگرنه SSD فقط برای اپلیکیشن.
7. (پیشنهادی) سرور Base با هارد SAS و RAID 10، 50 یا 60 برای Fault Tolerance.
8. (پیشنهادی) فرمت درایو C و درایو بکاپ با Allocation Unit برابر 64KB.

## ۴. نکات نصب
- نصب حضوری یا ریموت (RemoteDesktop یا AnyDesk). محتوای DVD نصب پیش از جلسه روی سرور کپی شود.
- نصب مجدد با داده قبلی: Backup و Database قبلی پیش از جلسه روی سرور جدید کپی شود.
- ماژول‌های پیامک، ایمیل، پیام‌گستر پرداخت، باشگاه مشتریان، فرم عمومی، لینک اشتراک‌گذاری و اپلیکیشن به **اینترنت** و برای دسترسی بیرونی به **IP Static** نیاز دارند.
- نصب نرم‌افزار و Database روی یک سرور ممکن است؛ جداسازی روی دو سرور بر اساس ویژگی بسته پشتیبانی (سایت) انجام می‌شود.
- آنتی‌ویروس پیش از نصب نصب شود و مسیرهای پیام‌گستر Exclude شوند (فهرست در `technical-architecture-security.md`). درایو پیش‌فرض نصب C است.

## ۵. ویندوز و دیتابیس
- **Windows Server 2022 یا Windows Server 2025** (Standard یا Datacenter). نصب روی ویندوز کلاینت (۷، ۸، ۸.۱، ۱۰، ۱۱) **ممکن نیست**.
- **SQL Server 2022 (Enterprise یا Enterprise-Core)**. پیام‌گستر Instance اختصاصی دارد که کارشناسان پیام‌گستر نصب می‌کنند؛ مشتری SQL نصب نمی‌کند.

## ۶. پیش‌نیاز ماژول‌ها
### ارتباط با مراکز VoIP
1. هسته باید **Asterisk** باشد. سخت‌افزار اضافه لازم نیست.
2. برای لاگ تماس و Click2Call، نام کاربری و رمز **AMI** لازم است.
3. نسخه‌های پشتیبانی‌شده Asterisk: **11، 13، 16، 18**.
4. داخلی‌ها باید در خود VoIP تعریف شده باشند (داخلی‌های سانترال که Trunk شده‌اند پشتیبانی نمی‌شوند).
5. دستگاه‌های Grandstream، Zycoo و Yeastar مدل U100 (Asterisk-base) با AMI پشتیبانی می‌شوند. ضبط مکالمه در Grandstream تنظیم API روی پنل می‌خواهد. پنل‌های Simotel، Sitak و Telsi با AMI پشتیبانی می‌شوند.
6. Cisco (CUCM) با TAPI و TAPI Driver ارائه‌دهنده VoIP پشتیبانی می‌شود (و هر VoIP با TAPI Support).
7. مدل‌های دیگر: پیش از خرید با واحد فروش برای بررسی فنی هماهنگ شود.
- مشتریان **AloVoip** هم باید ماژول ارتباط با مراکز تماس پیام‌گستر را تهیه کنند.
- RFI (Issabel): AMI در manager.conf، پورت TCP 5038، دسترسی خواندن CDR و مسیر فایل‌های ضبط، شماره داخلی هر کارشناس در پروفایل کاربر.

### ضبط مکالمات VoIP
ضبط باید روی خود VoIP فعال باشد. برای پخش در پیام‌گستر، نام کاربری و رمز **ROOT** لینوکس با دسترسی به فایل‌های ضبط لازم است.

### سانترال
سانترال‌های TDA یا TDE (پاناسونیک). برای تماس ورودی علاوه بر دو لاگ، لاگ RC هم باید نمایش داده شود. تست سانترال و لاگ HyperTerminal بر عهده مشتری است؛ تنظیم اتصال را پرسنل پیام‌گستر انجام می‌دهند. FAQ: TDA 200 پشتیبانی می‌شود.

### Caller ID (خطوط مستقیم)
دستگاه Caller ID برند تجاری **سگال** لازم است (سیم‌کشی بر عهده مشتری). در خطوط مستقیم می‌توان از دستگاه **تلسا (فقط نسخه ۸)** برای ضبط و لاگ تماس بدون سگال استفاده کرد. خطوط موبایل از راه GSM Modem.

### ضبط مکالمات سانترال و خطوط مستقیم (تلسا)
- تلسا نسخه ۶ و ۸. نسخه ۶ فقط روی ویندوز ۳۲ بیتی (۷، ۸.۱، ۱۰ یا سرور ۲۰۰۸). نسخه ۸ روی ویندوز ۶۴ بیتی. نسخه ۸ لایسنس دارد و نصبش با شرکت تلسا هماهنگ می‌شود.
- همه خطوط پیش از ورود به سانترال وارد دستگاه ضبط شوند. هر دو خط یک سوکت؛ ترتیب خطوط مهم است.
- در نسخه جدید، سانترال و تلسا می‌توانند روی سیستم‌های مختلف باشند. اگر تلسا روی سرور پیام‌گستر است، منابعش اضافه شود. **نصب تلسا روی ماشین مجازی توصیه نمی‌شود و انجام نخواهد شد.**

### فکس هوشمند
فکس‌مودم Voice Support (برای پخش پیام صوتی پیش از ارسال)؛ ارسال و دریافت از MSFAX ویندوز (یک مودم و یک خط کافی است). MSFAX فقط روی ویندوز ۷ و Server 2008 R2. نمایش شماره فکس دریافتی با Caller ID سگال و فقط روی خط مستقیم. **داخلی VoIP برای فکس پشتیبانی نمی‌شود.** ارسال با پیام پیشواز و دریافت با MSFAX دو مودم و دو خط می‌خواهد. در ویندوزهای غیرسرور فقط یک فکس‌مودم شناسایی می‌شود.

### پیامک هوشمند
سرور باید اینترنت داشته باشد. سه روش اتصال:
1. خط اختصاصی از تجارت اول (1st.ir، ۰۲۱-۴۵۸۵۳ داخلی ۷۰۱). **فقط در این روش وضعیت تحویل پیامک نمایش داده می‌شود.**
2. URL ارسال اپراتورهای دیگر با Query String (متد GET، UTF برای فارسی؛ شماره بدون ۹۸).
3. خطوط ۳۰۰۰ وب‌سرویسی با نام کاربری و رمز وب‌سرویس.

### ایمیل
تنظیمات Outlook (ارسال و دریافت) در اختیار کارشناس قرار گیرد. IMAP و POP3. Gmail فقط IMAP و با تأیید دومرحله‌ای. سرور اینترنت لازم دارد.

### یکپارچگی با سیستم‌های مالی
- سپیدار پایین‌تر از **۴.۶.۸** باید ارتقا یابد.
- پیوست، تدبیر، همکاران و راهکاران: نسخه مالی مربوط به **یک سال اخیر** و SQL مالی **۲۰۰۸ به بالا**.
- دسترسی به DB مالی با نام کاربری و رمز (همگام‌ساز: پسورد **SA**).
- همگام‌ساز روی DB مالی Attach می‌شود؛ پیش از هر تغییر در سرور مالی (مثلاً تعویض ویندوز) از DB همگام‌ساز Backup گرفته شود؛ وگرنه جلسه راه‌اندازی مجدد باید از باشگاه مشتریان خریداری شود.

## ۷. IP Static، دامنه و SSL (مسئولیت مشتری)
- دسترسی از بیرون: IP Static و Port Forwarding (پورت دلخواه مثل 8080؛ Internal و External برابر). با Ping و Telnet تست شود.
- دامنه (مثل crm.yoursite.com): IP Static، Port Forwarding، رکورد A در DNS.
- SSL: **SSL Valid** روی سرور. نرم‌افزار باید هم در شبکه داخلی و هم اینترنت **فقط HTTPS یا فقط HTTP** باشد؛ استفاده همزمان ممکن نیست.
- آماده‌نبودن پیش‌نیازها در روز نصب ⇒ نصب مجدد با هزینه طبق تعرفه سایت.
