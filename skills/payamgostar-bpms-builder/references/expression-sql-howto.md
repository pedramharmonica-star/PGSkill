# ساخت عملی: Expression و فعالیت اجرای دستورات پایگاه‌داده در فرایند

دانش کامل (نحو، جدول فیلدها، محدودیت‌ها به تفکیک نسخه، اشتباه‌های مستندات): `../payamgostar-knowledge/references/expression-and-sql-activity.md`. این فایل **روش کار** است: از نیاز تا دستور آزموده‌شده.

## ۱. کدام ابزار؟
| نیاز | ابزار |
|---|---|
| پر کردن فیلد با مقدار ثابت، تاریخ یا ساعت اجرا، یا گزینه ثابت | تخصیص مقدار ساده (بدون Expression) |
| پر کردن فیلد از فیلد دیگری در **همین آیتم، هویت مرتبط، سوابق یا آیتم پدر** | تخصیص مقدار + «عبارت» (Expression) |
| مسیر فرایند بر اساس مقدار یک فیلدِ آیتم دیگر | تصمیم چند شرطی + «عبارت» |
| خواندن از **جدول‌های غیر CRM** (محصول، ردیف فاکتور، کاربر، مدعوین) یا کوئری پیچیده روی دیتابیس پیام‌گستر | اجرای دستورات پایگاه‌داده (پایگاه داده پیام‌گستر) + «خروجی دارد» |
| خواندن از **دیتابیس SQL Server دیگر** | اجرای دستورات پایگاه‌داده (اتصال به پایگاه داده دیگر) + «خروجی دارد» |
| **نوشتن** در دیتابیس دیگر | اجرای دستورات پایگاه‌داده (اتصال به پایگاه داده دیگر) بدون «خروجی دارد» |
| تبادل با API یا وب‌سرویس (نه دیتابیس) | فراخوانی سرویس |
| آیتم جاری رسید یا حواله انبار | فقط SQL خام (Expression ندارد) |

ماژول لازم: «تخصیص داده پیشرفته» با پیش‌نیاز BPMS (و تناقض C58). پیش از قول به مشتری، نسخه نرم‌افزارش را با جدول بخش ۴ مرجع چک کن.

## ۲. گام‌به‌گام: از نیاز تا دستور
1. **جمله نیاز را دقیق کن:** «وقتی ___ (رویداد یا کارتابل)، فیلد ___ در ___ (مقصد) از فیلد ___ در ___ (مبدأ) پر شود؛ اگر چند ___ بود، ___ (قدیمی‌ترین، جدیدترین، با شرط ___)؛ اگر نبود، ___».
2. **مقصد:** آیتمی که فرایند روی آن است (فرایند را روی مقصد بساز). فیلد مقصد را با **همان نوع مبدأ** بساز (یا متن).
3. **نسبت مبدأ:** خود آیتم / `Identity` / `Children` (از روی مقصد ثبت شده) / `Parent` (مقصد از روی آن ثبت شده). مثال زنجیره: فرصت > پیش‌فاکتور > فاکتور.
4. **کلیدها:**
   - فیلد پیش‌فرض ← جدول بخش ۱۲ مرجع یا **کوئری‌ساز** پیام‌گستر.
   - فیلد اضافه ← «کلید کاربر» فیلد در شخصی‌سازی آیتم مبدأ + **کد زیرنوع** همان آیتم (صفحه شخصی‌سازی زیرنوع) ← `Field@SubtypeCode`.
   - نام جدول انگلیسی: `Form`، `Opportunity`، `Quote`، `Invoice`، `Ticket`، `Task`، `Contract`، `Appointment`، `PhoneLog`، `Receipt`، `Payment`…
5. **چند سابقه؟** اگر ممکن است چند سابقه از آن نوع باشد: `OrderDes(...CreateDate).Take(1)` برای جدیدترین، `Order(...).Take(1)` برای قدیمی‌ترین، یا `Where(...)`. نبودن سابقه ← `TakeOrDefault(1,"none")` (پیش‌فرض انگلیسی یا عدد).
6. **دستور را با قالب بنویس:**
   ```
   @(this.[Where(شرط).]Select(نسبت.جدول.فیلد[@کدزیرنوع])[.Order|OrderDes(نسبت.جدول.فیلدمرتب[@کد]).Take(n)]);
   ```
7. **چک کن:**
   ```bash
   python3 scripts/check_expression.py --activity assign --item Form --dest text --version 2.8.8 '<دستور>'
   ```
   خروجی «معنی» را با جمله گام ۱ مقایسه کن. ERROR = نچسبان. WARN = بخوان و تصمیم بگیر.
8. **جای فعالیت در فرایند:** فعالیت وقتی اجرا می‌شود که فرایند به آن برسد و مقدار **لحظه اجرا** را می‌خواند (زنده به‌روز نمی‌شود). اگر مبدأ سابقه‌ای است که بعداً ثبت می‌شود، فعالیت را **بعد از** کارتابلی بگذار که آن سابقه در آن ثبت می‌شود. برای به‌روزرسانی دوباره، فعالیت را در مسیر برگشت هم بگذار.
9. **تنظیم در نرم‌افزار:**
   - تخصیص مقدار: فعالیت جدید ← «تخصیص مقدار» ← برای فیلد مقصد تیک «اعمال» و «عبارت» ← دستور را (از Notepad، در یک خط) بچسبان ← حالت بعدی ← ذخیره. کادر قرمز = خطا؛ آبی ≠ تضمین.
   - چندشرطی: فیلد شرط ← «شرط جدید» ← عنوان، تیک «عبارت»، دستور، حالت بعدی؛ سپس حالت پیش‌فرض و حالت خطا.
   - SQL: بخش ۳.
10. **آزمایش** (بخش ۴) و **مستندسازی** در طرح (بخش ۵).

## ۳. فعالیت اجرای دستورات پایگاه‌داده
**مسیر:** تنظیمات ← شخصی‌سازی CRM ← نمای کلی ← ویرایش چرخه کاری ← فعالیت جدید ← «اجرای دستورات پایگاه داده».

**پیش از کار با دیتابیس دیگر (از تیم IT مشتری بگیر):**
- [ ] SQL Server (ترجیحاً 2017+)، نام سرور یا IP، نام دیتابیس
- [ ] دسترسی شبکه از **سرور پیام‌گستر** به آن SQL Server (پورت SQL)
- [ ] یک کاربر SQL با **حداقل دسترسی** (فقط جدول‌ها و عملیات لازم). رمز را خود مشتری در فعالیت وارد کند یا فقط در محیط او؛ در طرح، ایمیل یا مخزن نیاید
- [ ] نام جدول‌ها و ستون‌ها، کلید تطبیق (مثلاً شماره مشتری، کد ملی، کد کالا)
- [ ] یک دیتابیس یا جدول **آزمون** برای اجرای اول

**تنظیم:**
1. «اتصال به پایگاه داده دیگر» ← نوع «Microsoft SQL Server» ← رشته اتصال `Data Source:...;Initial Catalog:...;user id:...; Password:...` ← «تست» (باید پیام موفقیت بدهد).
   برای دیتابیس خود پیام‌گستر: «پایگاه داده پیام‌گستر» (بی‌رشته اتصال).
2. «دستور»: SQL، با Expression در قالب `@(...)` برای مقدار آیتم جاری.
3. خواندن ← تیک «خروجی دارد» و «پارامتر خروجی» = فیلد مقصد (فیلدهای مجاز در جدول بخش ۱۰ مرجع). نوشتن ← بدون تیک.
4. «حالت بعدی در صورت اجرای موفق» و «در صورت خطا» (پیشنهاد ما: خطا ← کارتابل «بررسی خطای انتقال داده» با مسئول IT).

**الگوها:**
```sql
-- خواندن از دیتابیس پیام‌گستر (رسمی)
SELECT @(this.Select(Children.Contract.FinalValue));

-- نوشتن در دیتابیس دیگر (رسمی)
update [Products] set [ProductName] = @(this.Select(Subject)); Where productId='...'

-- خواندن از دیتابیس دیگر با کلید آیتم جاری (الگوی ما؛ نحوه جایگذاری Expression داخل SQL مستند نیست، اول تست شود)
SELECT TOP 1 [CreditLimit] FROM [dbo].[Customers] WHERE [CustomerNo] = @(this.Select(Identity.CustomerNo)) ORDER BY [UpdatedAt] DESC;
```
- همیشه `TOP 1` و `ORDER BY` بگذار تا یک مقدار برگردد (اینکه کدام ستون/ردیف در پارامتر خروجی می‌نشیند مستند نیست).
- `UPDATE`/`DELETE` بدون `WHERE` ممنوع (اسکریپت چک خطا می‌دهد).
- کوئری را اول در SSMS روی دیتابیس آزمون اجرا کن، بعد در فعالیت.

## ۴. ماتریس آزمایش (برای هر دستور)
| حالت | انتظار |
|---|---|
| مبدأ وجود ندارد (هیچ سابقه، هویت بی‌مقدار) | فیلد خالی یا مقدار پیش‌فرض TakeOrDefault؛ فرایند گیر نکند |
| یک سابقه | مقدار همان |
| چند سابقه | سابقه درست (جدیدترین یا قدیمی‌ترین یا با شرط) |
| مبدأ لیست کشویی | Index می‌آید؛ چندشرطی بعدی متن درست را می‌گذارد |
| نوع | مقدار در فیلد مقصد درست نمایش داده شود (پول، تاریخ، کاربر) |
| SQL: دیتابیس در دسترس نیست | فرایند به «حالت خطا» برود |
| SQL: کلید تطبیق پیدا نشد | رفتار تعریف‌شده (خالی یا پیش‌فرض) |

رکوردهای آزمایشی در دمو با عنوان «(داده ساختگی)». روی سیستم مشتری فقط با اجازه صریح.

## ۶. خطاهای رایج
- کپی از Word یا تلگرام ← کوتیشن هوشمند `“ ”` یا نیم‌فاصله در کلید. از Notepad بچسبان.
- `=` به‌جای `==` در Where.
- `children`، `SELECT`، `orderdes` ← حساس به حروف.
- فیلد اضافه بدون `@کدزیرنوع` (از 2.7.5.3)، یا کد زیرنوعِ آیتم اشتباه.
- خواندن یک سطح عمیق‌تر: فیلدِ درون فرمی که فیلد مرجعِ یک **سابقه** است ← در تخصیص مقدار ممکن نیست؛ با فعالیت SQL یا دو مرحله تخصیص (اول در آیتم واسط) حل کن.
- مبدأ کاربر به مقصد متن ← GUID. مقصد «کاربر» بساز.
- فعالیت قبل از ثبت سابقه اجرا شده ← جای فعالیت را عوض کن.

## ۶-ب. مشاهده‌های دمو 2.8.8.2 (۱۴۰۵/۰۸/۰۹)
- روی دمو ماژول «تخصیص داده پیشرفته» فعال نیست. نشانه‌اش این است که در فعالیت «تخصیص مقدار» کنار «اعمال» **هیچ تیک «عبارت»ی** دیده نمی‌شود (حتی برای فیلد متن)، و نوع «اجرای دستورات پایگاه داده» هم در فهرست «فعالیت جدید» نیست. **پیش از قول یا تست، همین دو نشانه را روی سیستم مشتری چک کن.**
- در تخصیص مقدار، فیلد **تصویر** فقط بارگذاری یک فایل ثابت (Select) + «اعمال» دارد. فیلد تصویر در فهرست مقصدهای Expression هم نیست، پس کپی عکس از فرم دیگر با Expression **مستند نیست**.
- فیلد **«لیست آیتم سی آر ام»** (مثلاً لیست فرم‌ها) در فعالیت تخصیص مقدار **اصلاً نمایش داده نمی‌شود**. فیلد تکی «فرم» (آیتم CRM) با «انتخاب/افزودن» + «اعمال» نمایش داده می‌شود.
- «افزودن عبارت» در صفحه نوع آیتم، **فیلد محاسباتی** همان فرم است (EditExpression.aspx: گروه، عنوان، عبارت). این ابزار Expression فرایند نیست.
- فرم‌های آزمایشی روی دمو: «تست Expression - فرم منبع (داده ساختگی)» (کد `ExprSrc`؛ فیلدها `SrcImage` تصویر، `SrcNote` متن) و «تست Expression - فرم مقصد (داده ساختگی)» (کد `ExprDst`؛ `DstImage`، `DstNote`، `RefForm` فرم تکی از نوع ExprSrc، `RefFormList` لیست آیتم CRM فرم ExprSrc، `DstNote2`؛ چرخه: کارتابل «۲. بررسی نتیجه» و پایان `EndDone`).

## ۷. ساخت با مرورگر (ایجنت)
- کادر «دستور» فعالیت SQL ویرایشگر کد با شماره خط است؛ کادر عبارت در تخصیص مقدار یک فیلد متنی است. هنوز روی دمو با ایجنت امتحان نشده: پس از اولین ساخت، نکته‌های فنی (iframe، چسباندن، ذخیره) را به `browser-automation.md` اضافه کن.
- رشته اتصال و رمز را ایجنت تایپ نکند؛ از کاربر بخواه خودش وارد کند.
